# V4 legacy dispute coordination

Owner: v4/legacy; baseline 18afaa6. Scope: existing uptime/disputes*.py, fixtures/disputes/**, tests/test_disputes*.py only. No external requests or nested agents. Lead owns required real Opus review; this note is the review packet and API notice for lead and C.

## Consequential design choices (before implementation)

- Preserve frozen oracle/v1.json byte-for-byte. Freeze oracle/v2.json before code changes: four original dollar outcomes stay $100 cure, $0 correct denial, $100 disputed ambiguous, $80 awarded/$20 disputed partial. V4 adds explicit observed/available-at evidence timing. A maintenance notice already available before filing blocks the claim. A later-observed notice can corroborate a denial only after its recorded availability; initial filing and reply receipt times stay distinct.
- The stock cure remains an assisted, incomplete initial filing with later-available component evidence. policy_dispatchable becomes false for that initial packet. Complete-only automatic policy requires both summary and component now available, allowed classifications, valid immutable source artifacts and the exact approved minimized payload. Lead/C must update any old test or UI expectation that one approval automatically dispatches dispute-cure. This does not grant any real send authority.
- Invoice lines gain mandatory account/product/region/month/currency/invoice/evidence bindings. Missing or contradictory metadata fails closed. A 2025 incident cannot use the April 2026 governing agreement. Fractional-cent entitlement remains exact and eligible mathematically; automatic/assisted dispatch is held for human review when no settlement rounding rule can express it in cents.
- Canonical claim identity uses tenant, vendor, account, agreement, monthly obligation, product, region, month and channel; excludes case ID, incident interval and payload digest so duplicate/revised imports cannot create a second initial claim. One bounded supplement shares the obligation. SQLite reserves the obligation transactionally before simulator evaluation. Vendor records independently bind tenant/account/vendor.
- Outbound attachments use an allowlist before the simulator sees them. Raw source artifacts are separately pinned; immutable document bodies and append-only receipt/artifact records preserve approved content. Unknown raw fields cannot leak through a redacted classification label.
- WINDOW_CLOSED is checked against the actual initial receipt and governing local cutoff; a timely claim receiving a contradictory vendor code escalates to HUMAN_REVIEW. No blind expiry.

Tradeoffs: legacy wire supports one ordinary Twilio USD monthly interval, not a general contract engine. Required metadata is a deliberate fail-closed compatibility change for operator-provisioned dossiers. Existing seeded databases need revalidation against immutable source pins. Native correspondence modules remain C's ownership. This implementation remains a local simulator with synthetic evidence and UTC filing convention, not verified live contract enforcement.
