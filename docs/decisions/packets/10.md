# Local identity, interactive approval and simulation boundary
Prefer a single-operator process on loopback, random out-of-band reviewer bootstrap token, HttpOnly opaque short-lived database sessions, optional read-only viewer token, host/origin/JSON and custom-header CSRF checks, tenant fixed server-side. Actions offered from current authenticated stage; simulated credit posting/application from an existing award only. No role/tenant supplied by browsers. Alternative implicit localhost reviewer makes malicious browser traffic a risk; production SSO requires identity infrastructure and is out of scope. Integration tests will attempt forged role, cross-site POST, privilege escalation and duplicates. Recorded rehearsal uses synthetic principal and disposable DB. Never create fake human approval in delivered default state. No sandbox confidential payloads in model inputs or recorded offline demo. Evidence so far: five CP1 tests pass, real sandbox bills read, no write scope. Is interactive demo reviewer adequate and what should block production?
