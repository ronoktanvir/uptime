# Retained economic keys and ambiguous historical scope

The bounded correction preserves the deployed v2 economic key. It refuses new resource identifiers containing ASCII `/`, refuses regional identifiers containing that separator when the contract defines regional coverage, and reserves the ordinary resource name `aggregate-service` for the existing whole-service aggregate profile. An escaped or newly hashed key would let old and new representations obtain independent reservations without a verified alias migration. No migration or history rewrite is included.

The independent Opus50 review identified a second case: an old ordinary resource `cell/North` and a currently allowed regional resource `cell` in `North` produce the same retained remedy, `resource-month/cell/North`. An old ordinary resource `aggregate-service` likewise shares the aggregate profile's remedy. New claim intake now checks for an existing canonical initial reservation before appending its audit or claim row. Existing claim replay stays idempotent. Dispatch independently checks the original route, claim ID, exact full scope and supplement predecessor before any reservation or local financial event is committed. Copying the old owner cannot bypass the full-scope comparison.

Archived evaluations are projected from their exact immutable artifact and observation. When the original measurement tuple is ambiguous, the projection exposes `REVIEW_REQUIRED`, no current amount or grouping key, and the original `recorded_amount`. A positive affected contribution makes that stage's portfolio total unavailable. It is not omitted or counted as zero. The persisted evaluation, document, observation, case ID and reservation remain unchanged. Malformed or mismatched archive integrity still fails its existing verification checks; this readable refusal is limited to the identified economic-scope ambiguity.

The distinction between resource and region is contractual. Region enters this resource-month key only when the reviewed subscription establishes separately covered regions. A nonregional location label does not enter the remedy. Resource and region identities are exact: neither normalization, case folding nor URL decoding changes their bytes. Unicode slash look-alikes therefore do not alias ASCII `/`. Vendor and service labels retain their existing normalization. Version and source-document pins remain provenance, not new economic obligations.

`tests/test_economic_scope_delimiters.py` supplies synthetic legacy reservations for both collisions, restarts the current writer, and verifies rejected owner/scope substitutions make no SQL row changes. It checks exact retries, immutable original rows, and one supplement on the original key. Mounted signed historical receipt intake and local aggregate dispatch reject with identical inbox, delivery and reservation rows; new draft intake rejects before its audit. A finite identity-domain control includes case distinctions, percent sequences, composed/decomposed Unicode and slash look-alikes. Edge and empty identifiers are covered. Archived ambiguous fixtures return HTTP 200 with unavailable totals and byte-identical stored records.

A fresh-process control changes the actual `claim_identity.py` bytes and verifies that the reviewed evaluator digest changes. Existing activation controls refuse changed installed semantics, and the signed original-receipt control retains both its semantic version and source-document hash after activation becomes `REVIEW_REQUIRED`. Signed source pin tampering and attempts to replace original pins remain rejected by their existing tests.

This patch does not fence a concurrently running pre-v2 writer, establish that every historical deployment is collision-free, or authorize an alias migration. Root's read-only installed-database census is evidence about that installation only; deployment coordination remains responsible for retiring old writers. The authorized reversible correctness repair introduces no additional human approval step. Any later identity migration needs its own representation, collision census and append-only evidence-backed alias design.
