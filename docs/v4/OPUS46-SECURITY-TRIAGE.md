# Opus46 security triage

The tests reproduce an exception disclosure and a missing original-version pin for historical award attribution. The proposed draft-path bypass and active-vendor quarantine bypass do not reproduce. Native authorization follows the explicit separate-installation decision in ADR 0045 and the release protocol.

The reviewed source baseline is `64f077d`. The actual review used `claude-opus-5-5`, session `1c851e33-bd4f-4f6c-a646-b5604f5d8a20`, and packet SHA-256 `1b689017362415b6cf12bfa632ac9300999205c4ed244dac66059258b76112c7`. Its conditional findings are retained in [the review receipt](decisions/reviews/46-integrated-code-critique.json). All new observations below use synthetic identities, contracts and credentials.

1. **Native authorization, finding 1.** The observed early return is deliberate. `approvals_enabled` governs local consequential operations, while `native_install_ready` verifies a separate external installation authorization. The native binding checks that authorization again before provider use, alongside sandbox mode, tenant, business, exact config and per-action mandate/reviewer signatures. The launcher permits local approval mode only with replay and without native config. Adding the suggested global AND would make the separately authorized sandbox path unreachable through its intended launcher.

   `test_separate_native_gate_survives_local_switch_but_rechecks_native_revocation` exercises the mounted native preflight with local approvals and the local release callback disabled. A dedicated native authorization permits that protocol read, while a policy-write challenge returns 403. After native authorization is revoked, even replacing the challenge callback with `True` fails at the binding and produces no provider request. These controls use a mocked native provider and verifier. They establish route and gate behavior, without establishing an actual installed authorization or provider write. Operators stop native operations by revoking the independent installation grant or disabling its protected configuration. See [the release protocol](RELEASE-EVIDENCE.md).

2. **Raw-path normalization, finding 2.** The draft allowlist is a full match of `/api/vendors/[a-z0-9][a-z0-9_-]{0,79}/(candidates|tests|shadow-preview)`. Encodings, dot segments, extra separators, query fragments and trailing segments cannot satisfy it. The challenged path and subsequent raw request path must also match in `consume` before a reviewer principal is returned.

   `test_raw_socket_variants_cannot_borrow_a_canonical_draft_proof` starts the mounted app on a real loopback socket. It sends 22 raw variants directly through `http.client`, avoiding a client's URL normalization. Each variant is attempted both as a challenge target and with a fresh valid canonical candidate proof. Every variant fails to produce a successful draft handler response. The canonical control succeeds with identical raw and handler paths. This disproves the proposed draft classification bypass for the tested characters and mounted routes. It leaves the exact-path design intact.

3. **Draft quarantine and recovery, finding 6.** `transaction(..., draft=True)` invokes `check_write_draft` while holding the registry transaction. It checks the entire vendor history before parsing input. Any approved, active or revoked history denies draft mutation. The signed-route test activates a synthetic vendor using its full lifecycle, disables local approvals, then submits empty, invalid-date and identical-valid intake. All three are refused and the active version and revision remain intact.

   For an unpublished draft, `_fresh` explicitly sets `version=None`. Rejected intake therefore cannot trigger the same-version early return on a later valid submission. The recovery test imports a valid draft, quarantines malformed intake, then resubmits the identical valid terms. It returns to SHADOW with the original candidate version, a later revision and no approval actions.

   The exception-text concern is confirmed. A private marker in `overlay.effective_from` appeared in the HTTP quarantine reason through Python's date parser. The fix records a constant validation category. The view also sanitizes reasons from older immutable quarantine events, preserving their audit records. The new regression failed before the fix and passes afterward.

4. **Original contract version, finding 4.** The obligation key intentionally excludes version so republished terms cannot mint another monthly claim. Ordinary local filings recover their version from the original persisted approved packet, and the existing integration test rejects a different version even when the witness is enrolled for both. The placeholder passed to `claim_key` has no effect on the key because `_economic` deliberately validates and excludes it.

   Historical original receipts previously supplied no immutable version. ACTUAL_NATIVE required two independently enrolled and scoped signatures over the full registration, including its asserted version and receipt digest. Those signatures prevented silent payload changes, but both authorized witnesses could attest a different version. A public harness reproduced original resolver v1 followed by an accepted, explicitly dual-signed v2 registration. That failed the stronger requirement to match the original pinned economics.

   The correction adds optional source-signed `contract_version` and `contract_source_sha256` to the original filing receipt. The former follows the application's economic-semantics fingerprint convention; it does **not** include the source document bytes. The latter is the SHA-256 of the exact published document, verified against its stored source text by the active-publication resolver. Intake checks supplied pins against that scoped assessment and retains both in the receipt's authenticated digest. ACTUAL_NATIVE requires both digests and exact agreement between the original version and registered scope. The independently signed external-filing witness covers the original fact's full digest, which includes its source-content pin. A caller cannot supply a missing pin through the award registration. Older receipts missing either pin remain inspectable and cannot support actual attribution. The deduplication key is unchanged.

   The adversarial registration test enrolls two witness scopes, constructs valid signatures from both required roles, and confirms that the new version cannot replace the original pin. The original version still works. Additional controls reject an arbitrary `v1` label and a semantic pin lacking source content. Editing a signed registration, supplying only one witness, or changing the original receipt digest also remains refused. Mounted source tests check a source digest mismatch under the same economic version, signed-body tampering, and retention of the original pins after publication changes.

   This strengthens the content-binding condition in [Opus48](decisions/reviews/48-original-filing-terms-pin.json). The mounted attribution control also revokes the current catalog publication after the legitimate response. The claim then reports no current governing version, while the independently witnessed original remains attributed and a later exact-scope award succeeds. This establishes that this historical attribution path does not substitute the latest adapter for its retained original pins. The parent agent reports a read-only inventory of zero native credits in the installed sandbox; no awarded production records were inspected, rewritten or migrated by this change. Supersession remains blocked: there is no correction API or implicit reassignment to current terms. A future correction record must explicitly identify the original receipt hash and both old and replacement content/version pins, carry fresh registrar and independent vendor signatures, and record a named approver's decision. Its authorization and accounting effects require a separate reviewed design; this document grants neither.

5. **Native attribution after a permitted historical response, independent final review P1.** The independent review's frozen-source probe established one current attribution before a legitimate zero-dollar `submit-response`, then zero current attributions and `ORIGINAL_EXTERNAL_RECEIPT_REQUIRED` afterward. The existing condition rejected every nonempty submissions list, even while the authenticated original receipt and financial evidence were intact.

   The correction validates the original on its own and accepts only its single approved procedural supplement. The shared read-only claim-identity check requires exact tenant, case, scope, original receipt and digest, zero requested amount, procedural purpose, governing version when pinned, and the immutable HIST initial and supplement reservations. Route, step, packet digest, receipt identity, economic identity and timestamp must all agree. It performs no migration or reservation write during attribution. The original dispatch digest consequently stays stable after the permitted response.

   `tests/test_ramp_award_procedural.py` reuses the independent probe's app, signer, publication, native capture and office helpers without replacing the resolver, database schema or router guards. Its explicit fixture updates supply the original pins and office scope version from public claim GET fields. The original independent script remains unchanged. The corrected run retains the byte-identical original fact, `active_binding_count=1` and `RAMP_APPLIED_ATTRIBUTED` after the response, and accepts the subsequent independently signed award. Five corruption controls change the amount, duplicate the response, change its predecessor, remove its reservation or place the response before its original while adjusting the stored response timestamp to match. Each suspends current attribution and refuses the later award. Existing substituted-receipt and one-minor-unit overallocation controls also execute. Cash remains null throughout these generated protocol observations. The chronology and amount controls address the supplement falsifiers in [Opus49](decisions/reviews/49-economic-cardinality-and-compound-denials.json).

The narrow fixes do not grant approval, activation, financial or publishing authority. Shadow preview evaluates the enrolled reviewer's submitted facts. A private holdout's secrecy remains the independent evaluator's custody responsibility, and preview success supplies no blind-acceptance evidence.

Verification commands and durable receipts are recorded with the final commit. The primary new tests are in `tests/test_opus46_security.py`, supplemented by the existing native, vendor lifecycle, signed authority and award integration suites.
