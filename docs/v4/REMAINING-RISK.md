## Security and operational deployment

Public-key reviewer proof, exact scopes, immutable claim identity, independent source custody and transactional allocation address reproduced V3 defects. Independent before/after checks passed 118 assertions on their pinned V4 revision, while the original V3 failed 45. Later code changes still require a fresh complete regression run.

The local operator remains a trust root. They can alter the installation, enroll keys and replace application code. The service should remain loopback-only. Managed organization identity, customer consent, key rotation, retention/deletion operations, backup recovery, distributed workers, durable hosted webhooks and multi-tenant token custody require deployment engineering. Document hashes establish binding and detect alteration, while the enrolled source establishes who asserts the fact.

The release validator now checks substantive report content and source identity. It keeps genuine external sign-off separate from script-generated evidence. Credentials and independent private holdout fixtures remain outside the repository. All archived outputs require a final secret scan.
