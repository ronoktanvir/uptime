# Exact vendor context for captured bills

`sync_records` now defaults to `include_linked_vendors=True`. It extracts distinct native `vendor_id` values from successfully captured bills and drafts, sorts them deterministically, and reads `GET vendors/{id}` using the existing exact `vendors:read` grant on the injected provider. It accepts only sanitized same-ID responses. It does not fetch parent vendors, entities, merchant IDs, names, or guessed identifiers. Business authentication remains the provider's responsibility; a captured vendor is not independent evidence of business ownership or contract authority.

The vendor detail budget remains `detail_limit` **in total**, shared between linked reads and inventory reads. Linked reads take priority. The bounded vendor list still runs with the existing `page_size` and `max_pages`; only remaining detail budget serves inventory IDs. An overlapping linked ID is never read twice, including after a failed linked attempt. Duplicate inventory IDs produce an explicit issue. List payloads never overwrite canonical detail responses, even if they contain competing values. `include_linked_vendors=False` restores historical inventory-only behavior.

`resources.vendors.coverage.LINKED_VENDORS` reports unique referenced IDs (`listed`), attempted and successful detail reads, completeness, status and sanitized issues. Its `parent_scope=captured_native_records` explicitly limits it to captured parents. Its `list_complete` describes enumeration of those captured references, **not** enumeration of all bills or vendors. `coverage.vendors` retains the actual inventory pagination evidence. A complete linked set cannot turn a truncated inventory into a complete resource. Missing or inexact grants perform no vendor reads; failures remain unavailable/forbidden or partial, without broader-token fallback or retry. An exhausted detail budget reports truncation.

The join remains `bill.vendor_id == vendor.id` within the same capture. Vendor `default_entity_id` and `parent_vendor_id` are descriptive, not substitutions for bill entity or vendor identity. Archived bills and inactive vendors remain historical observations. Stale captures remain stale and unusable for evaluation under the existing loader policy. Consumers must retain those boundaries when presenting associations.

No record fields, schema version, checksums, or historical files are migrated. The validator accepts the additional coverage key while continuing to accept old snapshots without it. Names, contact information and raw payloads remain excluded. No label sidecar or vendor UI URL is implemented; “link” here means an exact native record association.
