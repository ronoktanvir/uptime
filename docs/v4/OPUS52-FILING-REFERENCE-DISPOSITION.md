# Grounded filing references: bounded correction and review disposition

The signed aggregate filing route could not express a supported service field when the service display name contained spaces: the resolver returned that Name, but the unchanged public `FilingField.refs` requires identifier strings. It also omitted singular `fee` and excluded every invoice row except the enrolled recurring line. A separately required excluded-fee field therefore could not cite its present signed row.

The fix changes only `correspondence_resource.py`. Service/product fields can cite the actual invoice or monitor event/source ID. A previously usable literal identifier remains accepted, without converting a display name into a new ID. A named recurring fee requires the enrolled recurring row. A named excluded fee requires exactly one present row whose signed category equals a declared exclusion. The field/category comparison uses explicit fee/charge vocabulary and grammatical words; this is bounded lexical equivalence, not a claim of arbitrary semantic understanding. Unknown descriptions, multiple category or row matches, and credit/refund/void/reversal/cancellation kind markers withhold the reference. A parent invoice reference is accepted for a named fee only after the matching row exists. No caller-selected ID becomes evidence merely because it has valid syntax.

The actual Opus52 review, session `90496b91`, raised four evidence concerns. The disposition is:

- **Contract authority and category provenance:** accepted and tested. Normal joins require the exact immutable `manifest.request_fields` set. Labels come from source-bound manifest phrases; category values come from the independently signed invoice content. Filing material supplies references, and cannot rename a field to select an undeclared category. The resolver never rewrites a signed category.
- **Parent invoice as service evidence:** the proposed line-level service enum was rejected because this existing aggregate protocol already represents one service. The full signed envelope and exact enrolled grant bind tenant/account/agreement/service/month; the stored claim must have that same scope. The join verifies plan, completeness, post-month timestamp and actual content hash. An unsupported per-line service ID or multiservice field fails the strict schema. The source must attest a scoped service statement; signatures do not establish the truth of a dishonest issuer's assertion.
- **Negative, reversed or ambiguous rows:** accepted within the existing schema. Negative amounts and added voided/reversed flags fail input validation. Credit-like or reversal kind markers cannot establish the requested charge. Distinct matching rows or normalized category ambiguity require review. No new status field or enumeration is introduced.
- **Historical replay and overfitting:** original source facts, their digests, exact filing fields and version/document pins remain unchanged. A current complete invoice cannot reconstruct missing historical filing contents. Newly replayed workflow decisions may improve after the bug fix; claiming unchanged recomputed dispositions would contradict the correction. Existing observed attempts remain preserved.

The independent studied additive cohort's first result remains **8/8 arithmetic evaluations and 0/7 denial dispositions**, with only 1/8 complete cases. No private inputs or gold were read here. New synthetic mounted regressions extend the committed Compass agreement and reproduce four failures before the patch. They check actual signed original filing, a separate mistaken denial and approved response, a correctly evidenced historical threshold denial, and refusals for wrong references, absent rows, reinstallation, installation credit, reversed kinds, multiple matches, filer injection and wrong issuer/scope. The negative fee controls also deliver a separately signed historical original and threshold denial: they stay in human review with no award or response authorization. Stored original evidence remains content-identical through the successful historical disposition.

The public JSON schema, provider/evaluator definitions, source-version conventions, reviewer mandates and correspondence parser are unchanged. The user authorized this reversible correctness fix; the review's additional blanket approval requirement was not adopted. All tests use scripted fixture authority and the isolated local outbox. There is no vendor or financial dispatch. The independent runner owns any later preserved original/additive attempts; a repaired studied cohort is remediation evidence, not a new generalization claim.
