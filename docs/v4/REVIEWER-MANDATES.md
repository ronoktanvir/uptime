# Exact local and native reviewer mandates

An offline administrator enrolls a named P-256 reviewer in one tenant's installation. The database assigns a random persistent workspace ID. A separate offline administrator registers an independently verified Ed25519 issuer public key, and any supported native actions and single Ramp business in its remit. A signature establishes possession of an enrolled key. Deployment records and tests cannot establish legal signing power or actual human review.

All local mutations for a non-default tenant require a current mandate. The default fixture tenant supports local reviewer simulation behind the deployment interlock. Every native dispatch requires a mandate for both the local POST and the exact provider effect, a sandbox-mode named reviewer, a fresh reviewer proof, and the separate operating controls in the workflow adapter. Financial approval or rejection is outside the native allowlist.

## Operator boundary

Keep registration and mandate documents under a protected operator-owned directory outside the repository, in mode 0600. The administrator must independently verify the issuer's identity, public key, business and operational remit before installing a registration. The HTTP API provides no enrollment, signing or grant endpoints.

1. Enroll the named reviewer using the launcher. Obtain the workspace and reviewer bindings with `python scripts/provision_mandates.py --db /private/operator/workspace.sqlite describe --reviewer alice.reviewer`.
2. Create a public issuer registration containing `subject` and a lowercase 32-byte Ed25519 `public_key` in hex. For native permissions add a canonical UUID `business_id` and an explicit list `native_actions`. Register the trusted file with `python scripts/provision_mandates.py --db /private/operator/workspace.sqlite register-issuer --registration /private/operator/issuer.json`.
3. The issuer independently constructs a `uptime.mandates.Mandate`. Use schema version `uptime-reviewer-mandate/1`, a fresh UUID `mandate_id`, the exact fields from `describe`, the issuer subject, Unix-second `valid_from` and `valid_until` at most 24 hours apart, the exact local POST `path` and SHA-256 of its exact raw request bytes in `body_sha256`. Use `effect: null` for a solely local mutation. Only one current mandate may match the request. Revoke superseded overlapping mandates before retrying.
4. For a native action, construct `effect` with `native_effect_from_request(trusted_business_id, method, absolute_api_path, raw_body).model_dump()`. Use the actual prepared request bytes. The function derives the resource type, operation and UUID from its path. It commits to the SHA-256 of compact JSON `["uptime-native-effect/1",method,path,sha256(raw_body).hexdigest()]`. The two supported operations are `POST /developer/v1/comments/bills/{id}` and `PATCH /developer/v1/blank-canvas-approvals/{id}/metadata`. [Comments](https://docs.ramp.com/developer-api/v1/api/comments) and [Blank Canvas approvals](https://docs.ramp.com/developer-api/v1/api/blank-canvas-approvals).
5. The issuer signs `mandate.signing_bytes()` with its external Ed25519 key. Those bytes are the full model's JSON using sorted keys, compact separators, ASCII escaping, and explicit nulls. Transport the document `{"mandate": ..., "signature": "<128 lowercase hex digits>"}` to the installer. Install with `python scripts/provision_mandates.py --db /private/operator/workspace.sqlite install --signed /private/operator/signed.json`. The server and installer retain public material only.
6. The named reviewer signs the exact local request using the ordinary challenge. The server atomically consumes the mandate even if the subsequent business operation fails. At the native boundary it verifies signature, issuer registration, reviewer key, time, revocation, installation, actual business and resource again. Native authorization expires after at most 60 seconds and consumes a second single-use ticket. An uncertain provider outcome requires the workflow adapter's reconciliation before a new authorization.
7. Revoke a mandate or all rights issued by one issuer with `python scripts/provision_mandates.py --db /private/operator/workspace.sqlite revoke mandate MANDATE_UUID` or `revoke issuer ISSUER_SUBJECT`. Revocations apply to subsequent checks, including a pending native ticket. Issuer re-enrollment uses a fresh subject and key.

Named issuer and reviewer identities must differ. Offline trust enrollment, custody of the signing key, sandbox credentials, the native installation's trusted business binding, and final dispatch checks belong to distinct operational steps. A file or secret copied into another installation cannot transfer a mandate because the signed workspace ID changes.
