# Capability matrix

The data origin, implementation depth and execution receipt determine each claim below. Local protocol tests exercise real code with controlled providers. A successful controlled call cannot establish permission on a live Ramp object. V3 remains preserved at `18afaa6`.

| Capability | Implemented depth | Evidence origin and current limitation |
|---|---|---|
| Ramp financial workspace | Sandbox business pin, resource scopes, bounded pagination, minimized immutable captures, identity joins, freshness, approval context, historical detail and read-only worklist | Actual sandbox observations. Six bills complete, twelve payees/card transactions/POs each sampled, eleven approval observations sampled. Refresh is an operator command. |
| Agreement association | Agreement listing/detail using the documented read-only POST, native vendor/PO/bill identity and effective-date metadata | Actual list returned zero. No governing signed agreement or quantities can be inferred from an invoice amount. |
| Price enforcement | Exact typed monetary arithmetic, amendment chains, exclusions, graduated usage tiers, service mapping, signed evidence package, capture/bill/line binding, revocation and operator CLI to authenticated case | General engine within documented USD/whole-unit/net-of-tax families. Real bills currently lack complete terms and line facts. Constructed caps stay separate and produce hypothetical discrepancies. |
| Twilio SLA | Contract-specific eligibility, cause/evidence requirements, excluded fees, time bounds, response preparation | Public-source rules with synthetic customer usage/fee facts. Historical seeded Twilio examples are limited demonstrations. No customer entitlement was established by the public incident feed alone. |
| Generic onboarding | Public document intake, model-proposition staging, typed compiler, customer overlays, independent shadow controls, version-bound promotion, rollback, new case dispatch | Genuine tool-free Opus extraction and signed application controls exercised. Supported rule families are finite. Frozen unseen documents have exposed unsupported semantics. Human approval in harnesses is scripted. |
| Additional evidence | Role-separated signed sources, immutable event identity, scope joins, aggregate/interval evidence, independent fee and request proof | Local synthetic source transports exercised. Provider account enrollment and production telemetry ingestion remain operator work. A client cannot declare itself an authorized evidence source. |
| Disputes | Authenticated asynchronous intake, independently witnessed original receipts, fresh unpredictable text, deterministic validation, correct denial/cure/partial/ambiguous handling, scoped source acquisition and appeal limits | General signed inbox exists. Semantic rules remain bounded. Unknown or conflicting language escalates. Historical seeded scenarios and third-party-style simulated replies remain clearly identified. |
| Adversarial counterparty | Independent contract arithmetic and source-evidence checks, deliberate conflicting and mistaken claims, fixed oracle controls | Entire counterparty is simulated. Its acceptance cannot establish vendor payment, credit issuance or real negotiation success. |

Current sandbox token lacks `bills:write`. No live comment was posted. A comment supplies review evidence, with no payment stop assertion. |
| Blank Canvas | Signed event and reset validation, exact active trigger, case-sensitive service, metadata/decision distinctions, controlled provider contracts | Configured procurement workflow and write entitlement absent. Internet-wide or multi-organization SaaS deployment remains outside the demonstrated runtime. |
