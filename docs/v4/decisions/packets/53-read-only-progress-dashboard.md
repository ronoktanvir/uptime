# Read-only localhost engineering progress dashboard

The user explicitly requests a quick localhost HTML dashboard with a Ramp-themed DAG of completed work, remaining work and dependencies, committed to their private GitHub repository. The design is an isolated static progress directory served on127.0.0.1 by a standard-library server. Only progress assets and an explicitly dated sanitized data.json are exposed. No application credentials, runtime database, private holdout or customer data is read. There are no financial actions or remote mutations.

Alternatives are adding this internal engineering view to the finance app's authenticated router, a build-system frontend with more dependencies, or a simple static view. Prefer static view to keep read-only project metadata separate and deploy quickly. A static data snapshot must describe its timestamp rather than implying automatic agent telemetry. Counts derive from DAG nodes, while test metrics name their exact code revision. Completion is per bounded task, with separate unfinished acceptance and external permission nodes. No inferred overall percentage or recovered money. Dependencies are validated as acyclic and links allow only safe HTTP(S) destinations.

Tests cover graph order, invalid edges/cycles, link handling, HTTP directory confinement and live DOM/mobile interaction. Existing application listeners are preserved and a free loopback port will be used. Publish HTML/JS/CSS/data plus the repeatable launcher. GitHub history and secrets checks continue. Rollback stops this isolated listener and removes the progress route artifacts in a later commit while preserving history. Review any misleading metrics, graph semantics, local file exposure or unnecessary architectural coupling. All displayed source counts are actual sanitized engineering observations. This authorized reversible UI requires no new commercial permission.
