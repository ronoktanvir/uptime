# Decision packet 88 — prepare a narrow local review exception

The user explicitly chose: “Prepare the limited exception for review.” Do not activate or sign it yet. Prior accepted packet87 preserved the full release gate; Opus recommended that any alternative be a written, time-limited, exact-workspace policy exception with no external/financial effects. This is preparation of that alternative, not retroactive release evidence. Only authored public fixtures and a local named account are involved; no credentials/customer data are shared.

Proposed implementation: a new, additive exception module and offline CLI, wired only into the dedicated Calyx reviewer launcher. Default remains existing local_release_ready. Stage a protected unsigned proposal pinned to the specific non-rehearsal replay workspace realm, tenant, origin, enrolled reviewer public-key hash, Calyx candidate version/dependency digest and tested source identity. Validity at most48hours; explicit person-run P256 signature over the exact reviewed proposal is required before an envelope can be used. Root stops at the unsigned proposal. No HTTP grant enrollment/signing endpoint.

When separately authorized, an explicit protected envelope file can enable only signed empty-body actions already offered by the ordinary Calyx registry: interpret, approve, activate and rollback. An outer route boundary rejects every other mutation, including candidates/tests/policy/source intake/claims/disputes/credits/native actions and encoded/query variants; auth challenges are limited to the same named reviewer and permitted action. Every challenge/action rechecks signature, workspace/key/version/current source, expiry and durable revocation. The launcher never installs a native configuration, model provider or inbound source grants. Test-only gate substitution remains confined to tests. Existing auth/gates/vendor engines are unchanged. Normal reviewer action proofs, state-machine revisions and source semantics remain mandatory. A separate append-only exception audit records scope/expiry; normal lifecycle audit identifies the exact signed actor/version. Rollback is terminal for this grant. No money or Ramp authority is granted.

Alternatives: complete the full independent release (stronger, not available now); remove the gate globally (reject); preserve observation-only (still available); limited exact capability (preferred for the requested preparation). Costs: helper/module, negative authorization tests, source/version binding and a person-operated signing handoff. Full locked suite after merge. No production-readiness claim.

Risks to challenge: route allowlist/canonicalization gaps; a generic Boolean gate accidentally enabling unrelated actions; copied workspace or changed source; expired/removed/revoked envelope being reused; reviewer-signed exception being presented as independent release approval; active adapter remaining recorded after expiry even though mutation/evaluation authority is blocked; replay-mode financial routes accidentally reachable. The policy owner/user must approve the concrete exception before activation. Same reviewer-key signature proves possession, not commercial identity or independent quality approval.
