# Source meaning and observation identity before monetary evaluation

The compiler and evaluator can turn an adverse source interpretation into a monetary shadow estimate even though activation remains gated. Exact token boundaries would prevent one demonstrated polarity error, but they would not repair negation, omitted conditions or raw observations impersonating opaque labels. This decision compares explicit source/evidence bindings with withholding monetary evaluation until a named reviewer accepts the semantic binding. The recommended direction combines those controls while preserving historical records and refusing silent migration.

Root reserved decision 61 and explicitly authorized this sanitized public-only Opus 5.5 consultation. No production change has been made for this decision. No private heldout inputs, oracles, real customer data, credentials or secret source were inspected or supplied. This packet is independent of correspondence decision 60, whose owner is considering response interpretation and effect authorization.

## Current mechanisms and affected consumers

`vendor_resource_terms.grounded` uses a normalized substring for plain string phrases. Stable-label dictionaries now use bounded whitespace normalization, but retain substring matching. Both forms therefore need consideration; repairing only dictionary labels leaves the plain-string path open. The compiler preserves whole-block original offsets/hashes, but stable bindings store a phrase and block identity rather than an exact subspan or semantic definition.

`norm` case-folds and joins runs matching `[^\W_]+`. The evaluator's `source_labels` unions normalized manifest labels with normalized bound phrases. `measured` then normalizes raw `symptom` and `cause` strings, after an optional overlay string-alias lookup, into that same set. Thus `successful_samples` and raw `successful samples` occupy the same namespace. No explicit definition reference, source digest or namespace marker is required in the observation. Fee exclusion categories also consume `source_labels`. Filing-field and fee-reference correspondence helpers read label phrases and perform their own role-based word matching.

Signed correspondence currently supplies `ResourceStatus.intervals[].symptom: Name` and `ResourceAttribution.causes[].cause: Name`. An overlay may contain `symptom_aliases` and `cause_aliases` string dictionaries. Their targets are checked against declared manifest labels; the alias dictionary itself is not an independent semantic authority. The correspondence owner requires original signed body scalars/bytes, event digests, source/semantic pins, filed packets and reservation identities to remain intact. A typed extension must be additive or explicitly reviewed, never a reinterpretation of an old literal.

The current `interpret` action comes after passing monetary tests. Test submission clears that interpretation field. Merely requiring the existing action before pricing would therefore create a circular workflow. A semantic binding decision must be available before monetary tests and be separately tied to the definition/overlay/evidence mapping, while final approval still binds the tested candidate and suite.

## Alternatives

### A. Exact source spans and typed evidence references

Compile each supported free-form definition into a distinct object bound to the exact public source digest, source block, original span, role and definition-set version. A lexical predicate checks complete token boundaries without reordering, case/punctuation folding, hyphen repair or fuzzy similarity. Whitespace handling retains decision 58's bounded equivalence and original source text. If a phrase has several possible source occurrences, require an exact declared occurrence or expose ambiguity; never select the first silently. A complete enclosing operative clause and any typed conditions must remain available to review. The exact tokenization rule, including underscore and Unicode handling, needs explicit tests.

This does not make fragments semantically sufficient. `successful samples` is a complete token sequence in a clause saying it never counts. Negation and omitted conditions need either already-supported complete operator semantics or an explicit named semantic decision; an exact span alone is evidence of wording, not positive effect authority.

Separate observation forms conceptually:

```text
literal observation: original observed text + source/report identity
definition reference: opaque definition ID + role + source digest + binding version
```

A definition reference must appear in independently authenticated evidence from the authorized source role and match the reviewed contract, tenant/account/resource/region scope. Raw strings do not become references, even if they exactly equal an ID. No replacement of spaces, underscores, punctuation or case can cross the boundary. A typed reference and contradictory raw text must not be silently reconciled. Literal text needs an explicitly reviewed mapping to a source definition; proposed opaque names have no ordinary-language authority. This avoids vendor-name filters or bans on words such as `successful` and `available`.

A binding decision records the named reviewer, exact source/definition set, role, original evidence representation, overlay/version, evidence namespace and relevant scope. Its digest participates in candidate compatibility and audit. A request body containing `reviewed: true`, a model rationale, an alias string or a passing suite cannot mint that decision. Scope/source/definition mismatches, stale reviews and unknown mappings abstain without money. Unsupported economic operators remain unsupported even after review; binding review cannot waive an unimplemented source condition.

Advantages: explicit source/evidence meaning and mechanically checkable identity; no raw-text alias collision. Costs: evidence-wire extension, caller coordination, compatibility handling and review workflow changes. Typed references still rely on correct signed evidence and competent semantic review; they do not certify that an outage actually occurred or that the reviewer interpreted a contract correctly.

### B. Review-first containment with the current wire forms

Keep current wire schemas initially, but mark unresolved free-form source/evidence bindings as requiring named semantic review. Candidate detail can expose source spans, proposals and unresolved definitions. Monetary shadow results, test actual amounts, workbench dispatch and current portfolio totals remain unavailable while that binding is unresolved. Do not manufacture an eligible amount and merely add a warning.

The reviewer must bind exact literal observations and any legacy alias maps to defined source roles before tests execute financially. This review occurs before the current interpretation/approval sequence, or replaces its semantic portion without requiring an already passing monetary suite. Final independent tests and activation authority remain separate. A binding survives unrelated test submissions only while its exact source/definitions/overlay/evidence mapping remain unchanged; final approval still pins the chosen suite.

Advantages: smaller immediate containment and no immediate signed-body rewrite. Costs: it delays useful monetary previews and concentrates correctness in review. If the raw/opaque namespace union remains in the evaluator after review, an accepted binding may still authorize unintended raw spellings. This option is insufficient as a permanent fix unless the accepted binding explicitly constrains those representations and enforcement stops union-based inference.

### C. Token-boundary correction alone, or lexical name bans

Token boundaries would stop `available` inside `unavailable`, but the preregistered negation, truncated-clause and exact opaque-string cases would remain exposed. Name bans fit examples and incorrectly give identifier spelling semantic authority. Neither is an adequate response to the observed financial effect.

## Recommendation for review

Use review-first containment as the initial safety boundary, then implement exact source-definition identity and distinct literal/reference evidence forms as the bounded durable mechanism. Do not ship token-boundary matching as a complete semantic fix. If the evidence namespace separation and review context can be implemented in one small, reviewed change, combine them; otherwise leave affected monetary evaluation unavailable until that mechanism is present. Preserve existing deterministic supported-class demonstrations and unrelated reviewed operators rather than suspending every adapter solely because it uses the resource family.

The trusted evaluator needs a binding context supplied by the server's reviewed artifact, not a caller-controlled field inside facts. A pure evaluator invoked without required context must abstain. Named review cannot authorize arbitrary executable code, unsupported economics or external filings. This packet proposes engineering authority boundaries; the independent adviser cannot supply the missing named human decision for any particular contract.

The strongest counterargument is that review-first containment reduces the usefulness of autonomous onboarding and complicates the existing test-before-interpret sequence. However, the measured behavior already assigns money to negated and nonoperative statements. An unaudited estimate is not a substitute for supported semantics. A small constrained complete grammar could replace review for a proven term family, but a general clause parser is outside this decision and requires its own evidence and review.

## Honest compatibility and migration

Do not mutate original proposals, signed evidence, reviewer decisions, candidate artifacts, event history, estimates, filed packets or dispatch reservations. Old acceptance is historical evidence, not authorization to apply a new interpretation silently.

For an affected installed artifact, mark current capability `REVIEW_REQUIRED` and exclude unresolved current monetary totals/dispatch until explicit source/evidence rebinding creates a new version. Preserve archived snapshots as historical records with their original version and uncertainty; do not rewrite settled or filed money. Existing source/semantic compatibility machinery already supports stale-version refusal, but the new rule must identify affected bindings rather than treating an arbitrary string conversion as migration.

Legacy raw observations and alias overlays remain readable. A new candidate can retain their exact original bytes and attach a separately authorized binding record, or refuse until replacement typed evidence arrives. Converting old `event_a` strings into definition references automatically is prohibited. Pre-existing human interpretation approval is not a binding decision unless it already names the exact required tuple; do not infer approval from its presence.

The economic obligation key and original receipt reservations must remain stable across a new definition/candidate version. If the new semantics make scope ambiguous, refuse reconciliation rather than inventing a new entitlement or rekeying published history. Rollback must not restore an unsafe raw-identifier inference path as current authority.
