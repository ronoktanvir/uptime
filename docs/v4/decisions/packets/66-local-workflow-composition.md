Instead fall through to existing mandatory signed mandate verification. Native actions remain rejected because rehearsal is true. Every claim/credit effect still needs an exact current mandate; no name-based Northwind exception or relaxed cap/scope check.
3. Generic GET `/api/workspace/workflow` returns `{workflow:null}` when no operator-owned package is configured. Configured data projects existing evaluations, claims, journal records, citations and history. Clients cannot select database, provider credentials, mode or proof level.
4. Generic signed POST `/api/workspace/workflow/actions/{action}` requests one currently offered action. Its opaque ID binds package/source digest, scope, current expected state and action, making an empty signed body an exact stable intent. A small durable command journal stores request identity and pending/completed/failed status; it is infrastructure state, never a forged domain completion. Repeated clicks return the same job/result and never advance a second action. Return the current projection with pending status; the UI polls. Only after the POST returns does an owned worker use the existing signed public API routes with separate current exact mandates. No nested lock bypass and no fake principal passed to financial methods. On crash, replay uses the same source event, receipt, provider and allocation identities and derives progress from authoritative records; errors remain visible, not converted to success.
5. Local ledger is an explicit provider namespace, not an alternate financial authority. It durably writes a credit/application with a UUID and idempotency key and separately reads back that exact UUID, payload/scope/currency/amount digest. Only a matching readback is eligible for existing AllocationLedger intake, with source DETERMINISTIC_REPLAY retained and exact mandate verification. Provider record IDs display as `local-ledger:<UUID>`, never as Ramp IDs. Posting and applying use existing award/scope/cap/date rules; no award may be created by the provider. Current bill balance is observed on the application date, with original invoice issue/service dates retained separately; it is not rewritten as a newly issued bill.
6. Seeder/rehearsal uses public catalog→shadow→tests→semantic review when required→interpret→approve→activate routes, demonstrates rollback and reactivation/version history without deleting audit, and leaves the final contract active. All source events cross signature verification. The declared event clock is fictional data in the isolated workspace; it cannot backdate any real deployment.
