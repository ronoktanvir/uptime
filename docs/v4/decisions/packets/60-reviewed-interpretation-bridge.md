# Decision 60: source-grounded proposals and reviewed interpretation bridge

## Question and evidence

How should the dispute engine handle unfamiliar wording without allowing an LLM to invent authority or financial facts? This packet contains code/design facts and newly authored public synthetics only. No customer records, credentials, private evaluator inputs or gold are included. Review the design independently, rank alternatives, challenge unsupported claims, and identify concrete falsifiers. Actual implementation is withheld until root reviews your response.

At frozen candidate `532c8d8`, the implementer's 72 public grammar cases and 646 scoped tests pass. A separately authored and sealed 100-case evaluation then returned `unknown` for all inputs: supported coverage 0/50 (12 availability, 12 lateness, 14 artifacts, 12 awards), mandatory-review abstention 50/50, unsafe accepts 0. The runner checked direct raw text, correct trusted context and a positive public control. These observations show a substantial coverage failure; they do not establish that an LLM will repair it. Private inputs remain hidden from this implementer. A separate studied eight-case cohort improved 2/8 to 5/8 completed, but three parser misses remain under independent diagnosis. Earlier failures remain separate measurements.

Source inspected at `797c3d0`:

- `Message` contains signed-envelope `receipt_id`, optional `credit_id`, and at most 3,000 characters of untrusted text. Source grants bind the complete claim scope. Intake only accepts the latest independently witnessed or locally submitted receipt; later contradictory correspondence escalates.
- `propose(text, claimed=None, scope_month=None)` returns a bounded `Proposal`. The finite parser remains the current admission path. In local `_reply`, a recognized proposal plus verified eligible evidence can draft a response, and a recognized award can update reported awarded money. Calling `_reply` with an arbitrary LLM label would therefore create a privilege boundary bypass.
- Historical replies have no authoritative original requested amount in the general receipt schema. Their local supplements are procedural and request zero dollars. A current estimate must not be substituted for a missing historical filed amount.
- Exact reviewer mandates bind local mutation path/body and, for filing, claim scope, packet and amount ceiling; source/evidence authenticity, contract version/source hash, chronology, duplicated obligations and artifact verification remain independent checks.

## Alternatives and costs

A. Keep extending finite regex templates. Minimal runtime latency/no model egress, but the sealed result shows no demonstrated unseen coverage. Further hidden-case-driven expansion would risk overfitting and weaker completeness. Retain existing successful behavior, not as the whole solution.

B. Let a structured LLM classify and pass the label directly to `_reply`. Best apparent automation and little user friction, but a valid JSON schema and copied spans cannot prove the meaning, negation, omitted objection, or source completeness. An incorrect award label could change money. Reject this authority model, even with model consensus/confidence.

C. Use a tool-free LLM only to prepare an explicitly untrusted interpretation draft, paired with a concrete human-reviewed, scope-locked bridge into deterministic previews and separately authorized effects. This is preferred. It adds provider latency, review time, state/schema/authorization work and more UI than a regex patch. It should generalize proposal generation across wording; that is a hypothesis to measure. It does not deliver autonomous unseen-message disposition by itself.

D. Manual source-span annotation with no LLM, using the same reviewed bridge. No external-processing risk and works for private text, but higher reviewer effort. This remains a complete fallback rather than a dead-end queue. Reviewed examples may later inform separately tested grammar additions; no automatic self-training or promotion.

E. Two models plus agreement, or a local model. These can be optional proposal quality experiments later. Agreement does not establish authority; local inference reduces egress but not hallucination, operating cost or approval requirements. Neither replaces C's boundary.

## Preferred concrete boundary

1. Preserve existing finite-parser behavior. An unknown reply stays `HUMAN_REVIEW`. An explicit reviewer request may create a separate immutable interpretation candidate; it never edits the signed message, injects a new source event, writes a synthetic reply, or calls `_reply`.
2. The server derives an immutable review context: tenant/claim, exact full scope/hash, current latest receipt and original receipt/fact digest, vendor event digest, exact text UTF-8 hash, original locally filed requested amount/currency (or explicit absent historical amount), pinned contract semantic/source hashes, evaluator version and state/evidence digest. A candidate stores that context digest, provider/model version, prompt/response hashes and provenance. Client fields cannot supply trusted context.
3. Candidate schema is a bounded list of propositions with a supported family or `unsupported`, literal source byte spans, explicit typed slots and uncertainty/conflicts. Every slot points to exact original bytes; identifiers preserve case, money uses the existing exact USD decimal constraints, stated amounts reconcile to the immutable filed amount where one exists, and stated periods match stored month. A full-text segment inventory records substantive spans, courtesy and unsupported residuals. Bounds, overlap, missing ranges, quote mismatches and fabricated references reject the candidate. These checks prove mechanical grounding, not semantic truth: even perfect coverage can hide an objection by mislabeling it.
4. A reviewer sees the locked original **entire** text, all spans and unsupported segments alongside the proposed meaning. The reviewer can reject, correct with new grounded spans, or attest an exact complete interpretation. The review is a separate signed, single-use interpretation decision bound to the whole context, proposed interpretation hash and exact response source. No bulk approval or model confidence threshold. Ambiguous, legal/commercial or unsupported assertions remain review-only; a checkbox cannot upgrade them into a supported family. The human's correctness remains a material risk, to be tested and disclosed.
5. Accepted interpretation allows a deterministic **dry-run disposition preview**, using current authenticated evidence/terms and original receipt chronology. It cannot manufacture a fact from model text. Normal response evidence gates, exact artifact mapping, monetary conservation, duplicate awards/claims, source pins and known deadlines apply. Historical amount-absent cases remain procedural-only. The preview identifies the chosen effect, required proof, packet/state hashes and amount; state changes invalidate it.
6. Interpretation approval is not effect authorization. Preparing a reversible response draft still requires a supported, independently evidenced preview. Filing retains existing exact approve/submit mandates. Recording a newly interpreted award or accepting/closing a denial requires a separate exact effect mandate, bound to event, interpretation, scope, terms, current state and money ceiling, and an audit entry. No grant of external vendor contact, settlement, waiver, cash, credit posting/application, or broader policy authority follows. Native/Ramp effects remain in their existing independent permission flow. Security owner must review the additive purpose/decision type: a generic `workspace` mutation cannot serve as a money authorization.
7. Duplicate review/effect requests are idempotent for the same immutable digest; different content under the same identity refuses. New evidence, reply, scope/term version, revocation or expiry invalidates pending approval at the transaction boundary. No new original filing or canonical obligation key is created. Disabling the optional adapter returns unknowns to the existing queue, preserving review history and prior ledger records.

This bridge connects novel wording to the existing supported financial/evidence families. It does not silently make novel commercial rules executable. Broad source/contract/evidence work continues separately; this is a new interpretation mechanism, not a reduction of dispute scope.

## Runtime privacy and operational limits

External inference is disabled by default. The first adapter may process only **explicitly approved public fixture hashes** from a server-owned disclosure manifest, including this packet's new public cases. A caller's `synthetic:true` flag is insufficient. Private evaluator files are expressly excluded even though they are synthetic. No customer text, confidential contracts, account identifiers, billing data, private gold, tokens, app settings, environment dump, database or repository context is sent. The adapter gets only the approved text, minimal approved synthetic context and schema. Manual review can use private text locally without a model call. Enabling real private processing would require separate exact disclosure authorization and a reviewed provider/data-handling configuration; that is outside this implementation.

Tool-free execution, empty working directory, no history/session persistence, no tools/MCP and no autonomous retrieval constrain the provider call. Initial limits proposed: one explicit call per candidate, bounded input/output, 60-second timeout, no hidden retry or model ensemble; failure leaves the claim unchanged. Audit provider identity, payload/response hashes, elapsed time and actual usage when available, without raw secret-bearing logs. No dollar price or performance claim is made without measurement; reviewer time may dominate economics for a small credit. Report proposal accuracy, mandatory-review false accepts, grounded-slot validity, review time, request latency, usage, completed authorized workflows and unchanged/no-action cases separately.

Do not report a candidate creation as a successful response.

Additional API/security tests to implement after review:

- A mocked malicious provider returns a perfect-schema award with fabricated, wrong, omitted, duplicated, Unicode-shifted or out-of-bounds spans; incorrect source/event/scope/amount/version/period; unknown slots; injected tool instructions. No effect or privileged evidence is created.
- An actual public synthetic provider call emits only a candidate with exact request/response hashes and reported model. Provider timeout, malformed output, model mismatch or disable flag leaves the existing workflow unchanged.
- Every byte of outgoing input is compared with an approved fixture manifest. Customer/private-evaluator input, forged disclosure flags, cross-tenant reads and auto-retries are blocked before provider invocation; a network spy records zero calls.
- A correctly interpreted unfamiliar denial traverses source authentication, manual interpretation review, deterministic preview and separate exact response approval/submission. Removing signed evidence prevents the response. An independently correct denial remains visible for an explicit closure decision, never model-driven concession.
- A partial award retains its pending remainder and cannot post/apply credit or move cash. Misstated remainder, second award, stale state/terms, absent historical filed amount, reused interpretation mandate, approval/effect conflation or replay cannot create money.
- Mutate grounding validation, completeness inventory, private-input preflight, context freshness, interpretation/effect authorization separation, and idempotency. Each mutation must produce a failing negative test.
- Freeze prompt/schema/candidate commit before a new independent corpus. Do not tune to the prior 100 private texts. Report safe abstention separately from supported proposal coverage and completed authorized workflows; keep all historical scores.
