# Decision packet 91a — the first real evidence source (D07)

Sanitized: public vendor status data and authored local identifiers only; no customer data, credentials or sealed evaluation material.

Team decision D07 (recorded November 9) selected a narrow published matrix: exact source imports plus customer overlays, USD, calendar-month periods; taxes, other currencies, partial periods, ambiguous amendments and business calendars return unsupported; no PDF intake; **one real evidence source onboarded end to end through the ordinary enrollment path**. It did not name the source. D11 keeps the app loopback-only. D06: humans gate judgment; evidence retrieval may run under scoped standing policies.

Available real sources. (1) Twilio's official public status feed (`status.twilio.com/api/v2/incidents.json`): public, credential-free, already fetched by an explicit opt-in refresher that pins the official URL, refuses redirects/encodings, caps size and stores a minimized snapshot with raw SHA-256 and per-incident content hashes. (2) Ramp sandbox bills: real reads exist, but they belong to the Ramp workstream, need credentials, and the observed bills have no governing agreement or line terms. (3) Customer telemetry or support systems: none exist for any real customer. Proposed choice: (1), for the `status` role only.

Implementation (done, 15 tests pass). A W5 module maps one verified snapshot plus one operator-selected incident to one signed `status` record for an exact enrolled grant, then the existing client signs and delivers it over the ordinary HTTP intake. Checks before signing: official origin; snapshot not collected after the clock and not older than 24 hours (public incident records can be edited later); vendor Twilio; grant incident equals the selected incident; incident resolved with a published start and resolution (creation time is never substituted); positive interval resolved before observation; the granted component is among the incident's published components; the decision-91 temporal rule for the grant month. Event identity is `twilio-status:<incident>:<content-hash prefix>`, so a retry is idempotent and an edited public record becomes a distinct record that the one-per-kind desk treats as a contradiction for review. The untrusted public label never enters the record. Local provenance records URI, observation time, raw hash, incident content hash and the explicit statements "customer impact unverified" and "month coverage not attested". The connector never emits a coverage record.

What it cannot show: customer impact, eligible fees, complete month coverage (W4 finding F3 makes the current Twilio profile treat one status record as complete; its owner is changing that under D07), or that the enrolled key belongs to Twilio (it belongs to the local operator who fetched the page). The ordinary launcher only accepts deliveries after the release gate verifies, and that gate is unsatisfied; a live end-to-end run would use the same app factory the test suite uses, in a scratch workspace with disposable keys, labeled as harness-hosted, not a release-gated launch.

Alternatives: wait for a customer telemetry source (none exists); use Ramp billing reads (other owner, credentials, no agreement); extend the status schema to carry snapshot provenance inside the signed record (shared schema owned by W0; D03/D04 boundary).

Critique in at most 250 words: is this a defensible reading of "one real evidence source end to end", what would make it misleading, any missing check, and whether the harness-hosted live run is acceptable evidence. Do not propose a review council.
