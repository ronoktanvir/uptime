## Choice and disagreement

Adopt Opus's explicit current-projection allowlist: unavailable availability observations contain identity, source/input evidence, citations, recorded history pointers and review diagnostics. Current `amount` is null; derived amount/rate fields are absent; the current trace identifies the unavailable version/reason without modeled money. Adding a new evaluator field cannot silently introduce it into this projection. Raw signed input evidence, quoted contract rates and explicitly named `recorded_amount` are historical/input facts, not current estimates. Immutable case versions remain the full historical record.

When a previously reviewed binding becomes stale, or the adapter implementation is incompatible, move `checks` to explicitly named `recorded_checks`, expose empty current `checks` and `checks_status=REVIEW_REQUIRED`. Empty checks never authorize an action. Newly executed unreviewed shadow controls retain their current null actuals and authored expected hypotheses; these are not stale prior successes. No retrospective edit makes an old test pass.

Reject same-scope qualifying/nonqualifying telemetry literal intersections alongside the existing causal and fee disjointness rules. Validation and stored-record loading use the same exact whitespace normalization as production `BindingContext.targets`; matching is case-sensitive with no aliases, prefixes, wildcards or fuzzy equivalence. Evaluation separately refuses a status matching both sets. Stored conflicts project as unavailable without rewriting or revoking stored authority rows. A read-only inventory function reports conflicts; the two actual local Ramp workspace files contained no semantic-review rows and remained unchanged during the recorded scan. Constructed legacy collisions are covered by tests.

Do not add a second current/history API or a generalized meaning service for this repair. Root declines Opus's demand for new human permission for these reversible API repairs: the user explicitly authorized security/correctness remediation, and repository consumers are coordinated centrally. No real review record is mutated, authorization widened or external action performed. Root also narrows the dispatch claim to examined routes; unimplemented export/webhook/search surfaces are not claimed to have been tested. Concurrent-read atomicity across unrelated dashboard requests and malicious in-process code remain outside this bounded evidence.

## Verification and rollback

New `test_semantic_current_projection.py` preserves the independent reproductions and adds an allowlist/future-field control, unreviewed-shadow negative control, transaction rollback on rejected review, read-only legacy scan/current refusal, and evaluator-time contradiction refusal. Focused result: **90 passed, 1 warning in 2.14 seconds**. Full locked regression and independent repair verification are recorded separately after the implementation commit. No existing assertion was weakened for this repair.

Rollback is a versioned source reversion on an isolated workspace, with the original failed probes demonstrating the defect it restores. Never reenable stale bindings, rewrite receipts or delete history to roll back. Actual Ramp databases were only opened read-only for the inventory; deploying the repaired semantic implementation still requires stopping older processes before opening a migrated database, as ADR61 documents.
