# Decision78: preserve an objection and a separate denial through review

Status: accepted, bounded implementation; final verification recorded in the workstream evidence.

## Problem and chosen boundary

Frozen public76 produced source-grounded availability and maintenance objections together with a separate negative award proposition. The mapper rejected every plural interpretation, so a reviewer could not preserve both meanings and use the existing deterministic objection policy. The browser also edited only the first proposition, and the review API permitted an omitted index to be marked `correct`.

The addition accepts exactly one positive, asserted, unconditional current-claim availability, time-bar or maintenance objection paired with exactly one negative, asserted, unconditional current-claim award proposition. The denial has no slots or specialized metadata. Both propositions remain in the review, audit and preview. Only the primary objection enters the existing deterministic policy; the denial adds no financial, closure or action authority. All existing singleton support remains.

Cure requests, downtime adjustments, competing objections, additional propositions, positive awards, amounts, conditions, quoted claims and other referents remain UNKNOWN in a bundle. Source-wide loss checks conservatively refuse money, partial-credit and condition cues and require explicit date literals to remain in the primary period slot. Unassigned durations are refused. These checks cannot establish complete semantic coverage of coarse overlapping source spans; explicit human source review remains mandatory.

## Alternatives and actual criticism

Keeping every plural interpretation UNKNOWN preserves the old limitation. Collapsing the denial into an objection discards a separately expressed meaning and was rejected. A generic planner for multiple objections would broaden authority and is outside this decision.

Actual Claude Opus5.5 critique session `cc9dd07d-5ee6-4817-9908-2f45506ed6a3` ran with read-only Glob/Grep/Read and no MCP tools. It identified hidden conditions, dates or partial credits within coarse spans; positional review confusion; the omitted-proposition review hole; and the first-proposition preview assumption. The lead adopted the narrower primary families, explicit rejection for omitted indices, identity fingerprints for each indexed comparison, source-wide guards and retained preview semantics.

The lead dissents from the critic's blanket percentage veto. An availability objection can legitimately compare measured and contractual percentages. Such literals are permitted only under an availability primary, with performance context in their own clause and without a credit-percentage or partial-award cue. This preserves the actual public76 source while withholding credit authority. The critic also proposed replacing positional resolutions with a new fingerprint-keyed schema. The bounded implementation retains the existing indexed API, records fingerprints of blind/candidate/reviewed content at each index and requires explained corrections for reordering; accept still requires exact equality at the same index.

## Review and product behavior

Every assertion has a separate editor and source reference. Restoring an independent reading or explicitly loading a suggestion preserves all propositions. Comparing a suggestion never accepts it. A missing reviewed index requires `reject`, and any rejection keeps the entire outcome UNKNOWN. Edits invalidate prior preview and reconciliation attestations. The preview identifies the primary assertion and preserves the denial as information only.

Scripted tests establish browser/API behavior, not actual-human review quality. Model source grounding is mechanical, not semantic truth. Existing exact draft approval, source freshness, evidence, financial conservation and external-action gates remain unchanged.

## Evaluation and rollback

The public76 inputs, expected answers, model requests/responses, saved annotations and baseline scores remain unchanged. `scripts/replay_dispute_annotations_78.py` replays those exact saved annotations offline, checks their frozen hashes and reports remediation mapping separately. It makes no model call, performs no human review and authorizes no action. The artifact-category miss is left unresolved; an identifier is never used to guess a document category.

New authored tests cover the bounded positives, adverse source semantics, review omission/reordering, source pointers and retained preview assertions. Relevant existing review, model-job and browser tests are run after source is frozen; exact results and failed attempts are recorded in `TEST-CHANGES-78.md` and the verification receipt. The parent runs the full suite after integration.

Rollback reverts the decision78 implementation and UI changes while retaining this decision, actual criticism/coding receipts and all evaluation evidence. It restores plural interpretations to UNKNOWN without altering existing financial engines or public proposal jobs.
