## Required controls

- Protected permission: client labels, hashes, extra provider/config fields and modified source cannot expand the operator's complete-request approval.
- Isolation: another tenant, subject, vendor target or job identifier cannot read or install the result.
- Idempotency and recovery: the same exact request resolves to one job; an access recheck recovers a lost response. A distinct retry nonce needs separate exact approval.
- Validation: wrong model/session, duplicate or non-finite JSON, contradictory values, incomplete source coverage, mutated receipt and stale dependencies refuse; no model-output repair.
- Financial boundaries: separate overlay validation, semantic bindings, current governing-fee evidence and normal human review remain authoritative. Missing money stays null.
- UI: source bytes survive input; edits invalidate access confirmation; stale async responses cannot replace newer state; quotes render as text; errors expose safe permission/action state rather than raw provider exceptions or internal paths.
- Compatibility: existing deterministic/local intake, signed draft restrictions and published history remain available. Any necessary existing label-only test change receives an exact ledger entry.
