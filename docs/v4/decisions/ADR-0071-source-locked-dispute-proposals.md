# Decision 71: source-locked public dispute proposals

Date: 2026-11-05. Status: implemented and verified on authored public controls; customer runtime remains disabled.

## Decision and evidence boundary

Add a separate, default-disabled public proposal adapter that asks a model for deterministic source-block identifiers and exact quoted semantic selectors. The adapter reconstructs UTF-8 byte spans on the server and passes the existing strict `Interpretation` grounding validator. Preserve the original raw-offset adapter and all review, financial, authorization and submission behavior.

This is a bounded interface repair, not evidence of general dispute understanding. Earlier public model results remain **0/4 fully compatible**, and earlier unseen private results remain **0/50 supported recognized, 50/50 mandatory-review abstained**. This work does not access, replace or rescore those private responses. The new eight controls are authored public synthetic development material frozen before code in commit `303ebed`; their SHA-256 is `16e994d2876a954a4847cab213488a47b5bd8e70c5a5ceaaffb82c1eb42b682f`.

## Alternatives and criticism

1. Retain model-generated byte offsets and improve prompting. This preserves detailed spans but leaves exact UTF-8 accounting to the model, an avoidable source of structural failure.
2. Add deterministic block identifiers and quote selectors. This moves byte accounting to code while preserving source bytes and strict validation. It sacrifices proposition-level location precision inside each block.
3. Weaken grounding or silently repair model JSON. Rejected: unsupported or omitted material must not disappear to obtain a successful score.
4. Use CLI structured output. The lead's actual probe found that `--json-schema` advertises and invokes `StructuredOutput` despite `--tools ''`. The predeclared tool-free gate rejects that transport. This increment explicitly uses the original plain output transport with a schema in the prompt; it does not silently fall back from a structured invocation.

Actual Claude Code Opus 5.5 criticism ran successfully with model `claude-opus-5-5`, session `d629ff10-01e1-4842-9aa2-560c2f694198`, tools exactly `Glob`, `Grep`, `Read`, and no MCP servers. The full local transcript is `/Users/ronoktanvir/.local/share/uptime-engineering/tasks/disputes-71/critique.jsonl`. This is an actual model invocation, not a simulated review.

Opus supported the source-block design and identified its decisive limitation: full byte coverage becomes mechanical when each proposition spans its entire block. A model can still omit the meaning of a condition, negation or second objection while supplying structurally valid output. Compatibility must therefore be reported separately from semantic mapping and operational review. Opus also found a concrete selector flaw: `$4` inside `$40`, or `$1` inside `$1,000`, can otherwise become a valid monetary slot.

The lead adopted token-boundary checks, deterministic original-order block IDs, complete block coverage and literal conservation. Broad cue-word and literal-count vetoes were not adopted: a blanket two-money-literals rule rejects a valid award plus remainder, and keyword rules do not establish semantic accuracy. Potentially supported single-proposition mappings with unassigned recognized USD literals or ISO/month-year date literals are refused rather than guessed. This finite literal inventory is not a complete language parser. Actual semantic false acceptance, if observed, is retained in the public result without changing the frozen expected outcome. Human source review remains mandatory.

## Implementation and validation

The initial Opus-selected coding process wrote `correspondence_blocks.py`, `correspondence_block_model.py` and the new block tests, but reached its 600-second bound. Its partial stream was not retained by the pre-existing bounded runner; its session and completed-run identity are therefore not claimed. The preserved code was subsequently tested. A bounded follow-up used incremental owner-only log spooling and completed in 38.6 seconds: actual `claude-opus-5-5`, session `0c9adcbd-739e-4e61-8cd2-f3c219646bb0`, tools exactly Edit/Glob/Grep/Read/Write, no MCP servers, seven actual Edit calls. It integrated shared `strict_json`, removed structured-mode support and strengthened the plain-only refusal test. One worktree-root search was denied by directory scope. The lead added the narrow literal-loss guard and tests. The [sanitized coding and criticism receipt](reviews/71-disputes.json) includes exact stream hashes and preserves failures.

The first frozen authored batch produced 5/8 strict JSON/schema/grounding-compatible responses but 0/3 supported positive mappings. The other three responses had Markdown fences and were refused without repair. Two negative controls mapped UNKNOWN; three were refused. No negative control produced a supported mapping. Inspection revealed generic prompt-contract omissions: polarity was confused with claimant-favorable outcome, artifact category prose was mistaken for an identifier, and a single award/remainder disposition was split into separate propositions.

`source_blocks_v2` clarifies those generic field meanings and requires bare JSON explicitly. It changes the complete request and hash; it does not retry the same request, strip fences, change expectations or relax authority. One separately labeled revised authored batch then produced **8/8 strict schema/grounding-compatible responses, 3/3 expected supported positive mappings, and 5/5 negative UNKNOWN mappings**. The award control maps exactly USD 17.20. No actual human review or operational compatibility was evaluated. These are single samples on authored controls, not a blind generalization result or a substitute for the unchanged private score. Both complete public request/response sets and model/session/stream hashes are in [the public evidence](../evidence/disputes-71-public.json).

Final focused verification passed **150 tests**. The existing manual-review/authority tests remain unchanged, including the rule that a reviewed award does not book a financial award. A new test explicitly demonstrates that structurally valid annotations can still omit a negation; human semantic review remains essential. The exact test ledger is [TEST-CHANGES-71.md](../TEST-CHANGES-71.md). An earlier full run was interrupted because source edits overlapped it; another was interrupted before the evidence-driven prompt clarification. Neither is counted as a full-suite pass. The final stable-source full suite passed **3023 tests**, with one existing Starlette deprecation warning, in 206.74 seconds. The [source-specific verification receipt](../evidence/verification-71.json) pins implementation commit `2c180e2`, source hashes and every retained check log.

The committed public-only evaluator is `scripts/propose_correspondence_blocks_public_71.py`; the [fixture README](../../../fixtures/correspondence/public-71/README.md) documents its explicit command. Omitting `--execute-public` was checked locally and refused with exit 2 before any provider initialization. The runtime customer model adapter remains disabled.

The initial supplied executable path `~/.local/bin/claude2.1.318` did not exist. The first launch failed locally before inference. The valid `~/.local/bin/claude` symlink targets installed version `2.1.318`; authentication was reused without copying credentials or changing HOME.

## Rollback

Remove the additive block adapter and its explicit public experiment caller. The original adapter, runtime-disabled default, strict interpretation schema, review workflow, financial engines and prior evaluation artifacts remain unchanged. No migration, external message, Ramp operation or customer model enablement is part of this decision.
