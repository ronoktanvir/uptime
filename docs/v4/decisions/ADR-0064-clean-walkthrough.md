# ADR 0064 — A coherent financial walkthrough with ordinary product views

Status: approved for implementation; financial and native proof remain separately measured.

## Decision

Build the requested Northwind story from versioned authored inputs in an isolated workspace, using existing financial evaluators, signed service APIs, state machines and allocation checks. Remove repetitive environment banners and classification badges from ordinary screens. Show document references, the configured destination, verification status, reviewer authority in record details and separate financial stages. Keep existing source and authority values in APIs and exports; add no hidden demo-mode flag.

The user explicitly authorizes fictional presentation data and will disclose it during the demonstration. That permits authored contracts and fictional counterparties. It does not establish a real customer signature, human approval, native Ramp delivery or cash recovery. Original live-proof gates remain unresolved until their evidence exists. The walkthrough is a separately tracked capability, not a replacement name for those gates.

The configured provider controls button wording. A local provider is named “Local ledger,” uses its own record namespace and cannot produce a Ramp-verified receipt. Actual Ramp posting uses the actual provider and exact-object readback. No Northwind terms are bound to an unrelated real Ramp vendor or bill. The existing connected workspace remains intact.

## Financial semantics and dependencies

The authored contract specifies a USD 12,000 monthly fee, 99.9% availability, 10% credit for each completed 0.1 percentage-point shortfall, a 100% ceiling and a 30-calendar-day receipt window after service-month end. Comparisons and increments are exact; the final currency rounding rule is written into the source. The March 1 amendment reduces the service-period cap to USD 11,000, independent of invoice issue date.

January supplies complete eligible usage and supports USD 2,400; February supplies complete healthy usage and is ineligible; March lacks required usage coverage and remains unknown. March pricing can independently detect a USD 1,000 discrepancy against a USD 12,000 invoice. The SLA credit base is the governing eligible service fee, excluding tax and unrelated items. Successive Estimated, Claimed, Awarded, Posted and Applied amounts are never added together. Applying USD 2,400 to a USD 12,000 bill leaves USD 9,600; the unresolved USD 1,000 pricing finding is not silently subtracted.

## Validation and rollback

Require boundary tests for exact availability thresholds, ceiling, rounding, amended effective dates, timely/late/missing receipts and leap years. Unknown usage must remain null through API and presentation. Verify duplicate actions, restarts, cross-tenant/currency refusals, partial or mismatched provider readback and source changes invalidating approvals. Record exact test changes; passing UI tests cannot replace financial or authority tests.

The actual full-suite result is recorded after each integration. No new result is claimed by this decision. Rollback disables the configured walkthrough and retains its records for inspection; it does not delete the connected Ramp workspace, original proposals, failure receipts or private evaluation material. No remote financial operation is required to remove a local walkthrough from the default view.
