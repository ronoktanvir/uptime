The next production change should remove the evaluator's union of opaque identifiers and raw source phrases, then require a server-supplied, role-scoped binding context before affected monetary evaluation. Keep the current signed literal evidence wire initially. Typed references are useful later, but they move rather than eliminate the need for an authenticated mapping. The decisive distinction is an observation's literal value versus a reference to a reviewed definition. Label spelling must never populate the literal-match set. Neither `event_a` nor `event a` is a reference unless it is carried in a distinct authorized representation. Legacy overlay alias dictionaries cannot self-authorize their targets. Enforce this across symptom, provider-cause, excluded-cause, fee-category and filing-field consumers, including direct evaluator calls, correspondence and current rollups.

A named semantic binding should pin the exact source/definition set and original spans, roles, enumerated literal representations, equivalence rule, evidence namespace, overlay and scope. The trusted server supplies the context; request bodies and test expectations cannot mint it. Source review needs the whole source and related occurrences/conditions, not a selected fragment. Unsupported conditions and missing referenced definitions continue to abstain. Reviewer identity records responsibility but does not prove interpretation correct.

Separate the binding from monetary tests and final approval. Reviewers can inspect the proposed meaning before numbers exist. A stable binding can survive test submission if its inputs remain unchanged; final approval must recheck the binding and pin the candidate, suite and binding digest. Revocation or changed mapping returns current capability to review. This avoids the present cycle in which interpretation is available only after monetary tests.

Token-boundary checks are necessary for the demonstrated substring error but insufficient for negation or omitted conditions. An automatic exception must be a separately validated, whole-block, complete grammar tied to compiled definitions and full-document material coverage. An adapter name, resource family or previously accepted demo is not an exception. No grammar expansion is proposed in this decision record.

## Qualifications and points requiring root choice

The review suggests an explicit Unicode equivalence in literal bindings. Do not add a new Unicode normalization by default: retain only the previously reviewed bounded whitespace behavior unless a separately specified mapping has authority. Confusables, format characters, punctuation, singular/plural, hyphens and underscores must not silently become equivalent observations.

The reviewer recommends separation of duties, attestations, optional lexical review flags and an additional reviewer for flagged clauses. A separate named human decision is already the central semantic authority under discussion. Additional reviewer-count or organizational-role policy needs explicit root disposition; this packet does not silently create a new approval requirement. A lexical flag may increase scrutiny, but its absence cannot establish source meaning.

The proposed store-level evaluator epoch is not sufficient by itself: an old binary that never checks that metadata can ignore it. Rollback safety must be demonstrated by running an actual older build against the migrated store or an enforced deployment boundary. Do not claim old-code refusal from an epoch field alone. The migration must also preserve immutable receipts and canonical economic identity; a new binding version cannot create a second entitlement.

Invalidate a binding when its actual source, definitions, mapping, scope or relevant evaluator semantics change. The review advises against invalidating solely for every unrelated compiler edit. Root should choose an auditable dependency digest rather than treating either all code changes or no code changes as the correct boundary.
