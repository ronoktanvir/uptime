# What Uptime can do inside a Ramp workflow

Ramp owns the bill, transaction, payee, procurement record, approval state and vendor-credit utilization. Uptime maintains the associated contract interpretation, evidence, disputes and reviewer decisions. A finding becomes visible to an approver in Ramp only after a supported write to a specific Ramp object succeeds. The evidence inspector can run independently of that write.

## Observed in this sandbox on November 4, 2026

The registered app used the client-credentials grant on `demo-api.ramp.com`. The first capture listed six bills and fetched each by its own UUID, including an open, pending USD 840 bill. All six used expense lines without a unit quantity or a unit rate. The list-agreements query completed with zero results. At least five transactions and five purchase orders were readable in the first bounded queries. The active vendor-credit query completed with zero results. The preliminary approval query omitted required entity IDs and returned HTTP 422. The subsequent bounded sync supplied real object IDs and returned eleven approval records. Its other sample counts were six bills, twelve payees, twelve card transactions and twelve purchase orders. Only the bill list and the empty agreement and credit lists completed. The provider also confirmed the sandbox business ID through the business read grant. A token with the right scope alone cannot establish that an object-level operation has succeeded. [Discovery and grants](evidence/ramp-discovery.json)

The app obtained `vendors:read`, `bills:read`, `transactions:read`, `purchase_orders:read`, `approvals:read`, `unified_requests:read`, `custom_forms:read`, `spend_programs:read`, `spend_requests:read` and `custom_records:read`. A request for `bills:read bills:write` returned only the read scope. Write-only requests for `bills:write`, `transactions:write`, `spend_requests:write`, `blank_canvas:write` and `custom_records:write` yielded no reported grant. The registration settings require a signed-in administrator. The OAuth response cannot distinguish a disabled allowed scope from a product entitlement or a restriction on that app. [Bill scope exchange](evidence/ramp-bill-grants.json) · [Ramp developer app configuration](https://support.ramp.com/accessing-the-developer-api)

## Interfaces and implementation boundary

| Surface | Supported use | What must be true |
|---|---|---|
| Bill Pay and purchases | Read bills, drafts, approval state, inventory/expense lines and linked POs. The bill's `deep_link_url` and the PO's `ramp_url` are provider fields. Use the native record as the review destination. | Stable UUID plus correct sandbox host. A PO discrepancy can support a procurement finding. Negotiated pricing also requires applicable terms and line/date/fee identity. [Bill Pay](https://docs.ramp.com/llms-guides/bill-payments.txt) |
| Bills, payees, transactions and agreements | A read-only POST to `/vendors/agreements` lists agreements. Detail can provide payee, dates, lines and POs. Card transactions identify a merchant. | Link records by documented native identifiers. A merchant display name and a bill-pay vendor name alone cannot establish that two entities or agreements match. [OpenAPI](https://docs.ramp.com/openapi/developer-api.json) · [Data relationships](https://docs.ramp.com/llms-guides/data-relationships.txt) |
| Native discussion | Add a redacted finding to the bill, draft-bill, transaction or spend-request thread and verify the resulting comment in that exact thread. A note supplies information to the approver. | Resource-specific write scope, any additional product access, current object and exact authorized finding. A comment does not stop payment. [Comments API](https://docs.ramp.com/developer-api/v1/api/comments) |
| Blank Canvas | Handle the external approval request and reset events. A configured step can display a status and inspection URL. Approve/reject is a separate endpoint that changes the workflow. | Custom API workflow access, a configured node and matching case-sensitive service key, signed event, current trigger instance, authoritative request/form/workflow context and `blank_canvas:write`. A procurement request and a bill have different IDs. [Procurement integration](https://docs.ramp.com/llms-guides/procurement-intake.txt) |
| Vendor credits | Read the credit, remaining and applied amounts, bills and draft reservations. Cross-check the native credit against the corresponding bill and an independently verified award. | The published vendor-credit routes provide listing and retrieval. Credit creation and application require a supported Ramp operator workflow. Draft reservations and filed claims are separate from applied bill amounts. [Ramp API schema](https://docs.ramp.com/openapi/developer-api.json) |
| Webhooks | Subscribe, verify the callback challenge and validate the HMAC-SHA256 hex digest over exact raw business-event bytes. Deduplicate deliveries and refresh the native object. | A registered public HTTPS receiver and the subscription secret. A local signed rehearsal cannot establish a live subscription. [Webhooks guide](https://docs.ramp.com/llms-guides/webhooks.txt) |
| Custom Records | Extend supported native objects, including bills, transactions, vendors and contracts, with configured columns. | The schema, product access and `custom_records:write` must be available. Native table extension is distinct from installing an arbitrary page in Ramp. No public arbitrary-page embedding interface was identified in the inspected materials. [Custom Records](https://docs.ramp.com/llms-guides/custom-records.txt) |
| Ramp CLI and MCP | The official CLI or MCP can operate with the signed-in user's effective role and business controls. The sandbox MCP host is separate from production. | Separate browser OAuth consent and the user's permissions. The current Codex catalog search returned no connected Ramp plugin. The official CLI was checked from pinned source; its sandbox human profile reported no authentication. [CLI](https://docs.ramp.com/developer-api/v1/cli) · [MCP](https://support.ramp.com/ramp-mcp) |
| Third-party distribution | Customer-authorized OAuth authorization-code and refresh flows can support an installed integration. Client credentials support this internal sandbox application. | Customer app registration, consent, secure tenant-isolated token custody and any partner/product approvals. No multi-business OAuth installation or App Center listing was established here. [OAuth](https://docs.ramp.com/developer-api/v1/scopes) |
