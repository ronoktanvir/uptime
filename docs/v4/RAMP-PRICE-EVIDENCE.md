# Price evidence for an installed Ramp bill

The offline finance operator binds negotiated pricing to one bill on the latest ready capture of one installed sandbox business. The application can reconstruct a price check only while the issuer, signature, exact bill and line digests, supporting document bytes, evaluator build, and time window still verify. Results remain provisional and carry no provider write authority.

## Provision and sign

Use the workspace Python environment. Keep the private key with the independent finance issuer. An installation administrator must establish that issuer's organizational remit and verify its public key out of band. The administration CLI accepts only operator-owned 0600 files in protected directories outside repositories. The workbench exposes no HTTP key-enrollment or price-package upload route.

1. Use `python scripts/ramp_bind_terms.py --db WORKSPACE describe --tenant TENANT --business BUSINESS --bill BILL` on a workspace populated by the ordinary authenticated sandbox importer. The output provides the installation realm, capture and bill digests, party IDs, evaluator pin, typed bill line digests and linked purchase-order line digests. A fresh capture is required within 24 hours.
2. Use `python scripts/ramp_bind_terms.py schema registration` and `schema packet` for the exact JSON contracts. Register the protected public registration with `python scripts/ramp_bind_terms.py --db WORKSPACE register --registration /private/operator/finance.json`. It pins the issuer's public Ed25519 key, tenant, persistent workspace realm, Ramp business, vendor, customer entity, and either `SYNTHETIC_NEGOTIATED` or `OPERATOR_ATTESTED`. Each issuer key serves one purpose and scope. Duplicate keys, customer or source identities used as finance keys, and revoked key re-enrollment are refused.
3. Store the exact document bytes for each agreement version and each service/quantity/tax allocation in a protected evidence directory, each under its lowercase SHA-256 filename. The files may share a digest if they genuinely cite the same artifact. Each version specifies the opaque clause section, signature/effectivity timestamps, both party IDs, amendment predecessor, rates, graduated tiers and excluded products. Each bill line specifies its exact digest, product, unit, service interval and supporting evidence digest. PO-based quantity additionally requires the captured PO and PO-line identities and digest; the issuer must review evidence that the entire PO-line quantity was billed. Every bill line must reconcile to the native bill total.
4. Set an expiration at most 24 hours after the issuer's approval time. The signed purpose and economic basis are fixed fields. The issuer vouches for the complete governing contract history, scope, quantity, service dates and net-of-tax basis. This path supports completed service periods, USD, whole-unit quantities, positive graduated rates, and contractual line-level half-up cent rounding. The synthetic registration yields the corresponding mixed-data finding even if the input document describes itself as signed.
5. Produce the precise bytes with `python scripts/ramp_bind_terms.py signing-bytes --packet /private/operator/price.json --out /private/operator/body.bin`. Review the source documents and economic inputs, then sign those bytes locally with the registered Ed25519 key in the issuer's signing tool. The signing input is UTF-8 canonical JSON of the two-element array `["uptime:ramp-price-evidence:ed25519:v1", validated_packet]`, with sorted keys, compact separators and defaults materialized. The installer accepts the 64 raw signature bytes in a separate protected file.
6. Install with `python scripts/ramp_bind_terms.py --db WORKSPACE install --packet /private/operator/price.json --signature /private/operator/proof.bin --evidence-dir /private/operator/evidence`. Check the resulting package using `python scripts/ramp_bind_terms.py --db WORKSPACE status --tenant TENANT --business BUSINESS`. The database keeps the signed economic inputs and private evidence-directory location. Raw contracts and service documents stay in their protected files. Document bytes and private paths are excluded from the status report.
7. Revoke with `python scripts/ramp_bind_terms.py --db WORKSPACE revoke package PACKAGE_UUID --tenant TENANT --business BUSINESS` or `revoke key ISSUER --tenant TENANT --business BUSINESS`. Revoke an obsolete package before installing a competing one for the same capture and bill. A refreshed capture requires a fresh review and signature, even when the bill ID is unchanged.

`RampTermsStore(path).bindings(tenant, business_id, snapshot)` returns the verified typed bindings for `evaluate_snapshot`. `resolve` also returns sanitized omissions. Single-use installation/reviewer mandates and any native authorization remain independent. A finance attestation establishes the registered key's assertion about the supplied documents. Verification of the original parties' legal capacity and signatures belongs to the finance review.

The command-level tests build itemized synthetic bills using the real snapshot normalizer and importer. Their keypairs, governing documents and service evidence are disposable controls. A sandbox bill lacking itemized evidence cannot acquire a monetary result through this path.
