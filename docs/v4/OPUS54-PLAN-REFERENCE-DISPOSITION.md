# Signed plan references within the existing aggregate join

On base `38bca3e`, public `projection.filing_fields` cites the invoice source ID for a required plan field, while `filing_refs` accepted only the literal reviewed plan. A new public Compass regression with a source-bound required plan reproduces four failures for the invoice/monitor source and event IDs; the literal `Marine` control and 16 negative controls pass. Root's separate independent diagnosis reports the plan reference as the sole refusal in all seven additive workflow packets. This implementer did not inspect the private cohort, gold or attempt evidence.

The correction adopts Opus54 alternative A: plan/edition may cite only the existing `service_invoice` or `service_monitor` event/source IDs in the dictionary consumed by this same filing's join. There is no source-store lookup. `join_service` first requires both records, the correct authenticated source kinds, unique statement kinds, complete post-month records, valid content hashes, and each signed `body.plan == overlay.plan` without normalization. Ingress separately binds the full signed scope to the enrolled source grant and stored claim. The signature covers plan metadata as well as content. A fee-line ID or filing-material ID does not attest a plan and remains unsupported.

The public wire type remains `Id`. A valid literal plan ID remains compatible; no display name is converted into an identifier. `ServiceRecord.plan` already uses `Name`, which permits internal spaces. A separately reviewed synthetic `Marine Plus` plan therefore accepts its actual source ID, while putting `Marine Plus` directly into `refs` still fails schema validation. This demonstrates an existing protocol capability, rather than changing the protocol to fit a private input.

Opus54's blanket literal/source-ID collision refusal was not adopted. After successful joining, the literal interpretation denotes the reviewed plan and the source interpretation attests that exact same plan in both reports. The collision test files with invoice source ID `Marine` and plan reference `Marine`; changing the signed invoice's plan to `Different Plan` with that same ID withholds eligibility. A collision does not provide a path around plan equality. Duplicate source kinds, including a later statement with another source ID, fail closed; no implicit supersession selects an older statement.

The mounted controls exercise actual original approval/submission, independently signed denial and approved reply; wrong plan, missing plan, wrong issuer, wrong service/account/agreement/month, missing source, unknown or line-only references, source-body signature tampering, field injection, and cross-claim source borrowing. Case changes remain unequal; leading/trailing whitespace and Unicode values fail the existing schema rather than being trimmed or normalized. A historical original missing its plan field remains incomplete even with a complete current invoice; its stored original object and provenance pins stay unchanged.

These are synthetic negative-control processes, not deployed relaxations. Their receipts record failing authority tests and the exact mutated source hashes.
