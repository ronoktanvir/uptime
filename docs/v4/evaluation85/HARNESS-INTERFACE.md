# Public phase85 harness interface (implementation contract)

This test control is authored for harness mechanics only. It is not the independent84 corpus, gold, a model result or real customer evidence. Only document text and existing extraction instructions are transmitted. Local customer data and expected outputs never enter the request. No actual corpus input or gold is available to this worker.

`scripts.evaluate_onboarding_85.prepare_case(*, case_id, family, document_path, customer_path, document_sha256, customer_sha256, config_path, attempt_dir, tenant, subject)` creates a NEW0700 outside-Git attempt directory and0600 immutable files. Source input names must be exactly document.json/customer.json, never expected.json. SHA arguments are exact raw file SHA256 from independent freeze. Opaque catalog targets are derived from the source file hash; no case/family label enters the request or target. Family labels: monthly_tier/completed_step/unsupported_variable_fee/ambiguous_deadline→monthly-propositions; resource_month/aggregate_fixed_month→resource-month. Unknown labels refuse. Document strict shape; customer has overlay+scenarios, plus optional local classification and raw governing_fee_source from the frozen84 author schema; each scenario exactly name+facts (no expected). Raw fee documents never become fee authority. It returns dict with profile, request_sha256, context_sha256, case_id. It writes document.json/customer.json raw, request-export.json (existing readable operator export), request.json (exact canonical transmitted request), frozen.json (pins). No provider.__call__, approval, queue, DB or key creation in prepare; CLI constructor help/version only.

`run_attempt(*, attempt_dir, config_path)` verifies frozen file/core/source/request/profile pins; writes run-started.json create-only; starts disposable signed loopback app through existing create_app and actual PublicProposalJobs; reads existing protected approval before invoking; performs one POST proposal-jobs (never retry); polls GET; installs only valid SUCCEEDED job via candidate route; calls signed shadow-preview for each local scenario. No tests/meaning review/interpretation/approval/activation/native effect. Missing authority stays unknown. Re-entering any started attempt raises FileExistsError and makes no call. Drift must be a retained failure with zero provider calls.

Return report: {case_id,profile,failure_stage:null|"frozen_inputs"|"permission"|"extraction"|"shadow"|"evaluation"|"runtime", extraction:{status:SUCCEEDED|REFUSED|UNCERTAIN|NOT_ATTEMPTED,job_id?:...}, shadow:{status:SHADOW|QUARANTINED|NOT_ATTEMPTED}, deterministic:[{name,http_status,result}], authority:{promotion_performed:false}}. Raw structured public response and transport receipt are retained separately; no stderr/stdout/secrets in public report. Create-only report.json and progress.jsonl preserve partial states. The parent may refine error details but not these gates.

Existing public interfaces, exact locations: `uptime.vendor_model_jobs.build_vendor_provider`, `.public_approval_request`, `.ProposalRequest`; `uptime.public_proposal_config.PublicProposalConfig`; `uptime.source_config.load_private`; `uptime.contracts.DraftReviewer`; `uptime.public_proposal_jobs.canonical`; `scripts.public_proposals.approve`; `uptime.auth.enroll`; `uptime.auth_keys.generate_reviewer_key`; `uptime.auth_client.ReviewerClient`; `uptime.server.create_app`. prepare and actual config factory both use `uptime.vendor_model_jobs.build_vendor_provider`, so tests can monkeypatch that single factory. Provider double must expose model=uptime.vendor_model.MODEL, system=VENDOR_SYSTEM, fixed nonempty dict profile, __call__(request:bytes)->{model,session,text:<bare JSON string>}; optional last_receipt. No real inference in tests. The executable in protected config may be /usr/bin/true when factory is patched. Use existing protected approve(request-export.json, approvalspath, approved_by=..., expected_digest=..., public_confirmed=True) in tests; this is explicit authored test inference permission only.

Root owns .venv and final full suite. No existing tests may be weakened. Parent implements runner; worker owns only new tests/test_onboarding_evaluation_85.py.
